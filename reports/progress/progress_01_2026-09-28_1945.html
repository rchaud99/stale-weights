Stale Weights: progress report 01

2026-09-28, 19:45 EDT · round 3 · Qwen2.5-14B seed 0 only · all numbers from results_r3/ and earlier result files
Where things stand. Round 3 set out to replicate and stress-test the one result that survived last round: when a prompt leaves out the refund-window rule and says "apply only the rules written in this policy", a model fine-tuned on old decisions still applies its old window, while the same data trained with the policy text in the prompt does not. After about 45 minutes of GPU time the user stopped all GPU work, so only part of the first experiment (mitigations on the existing seed-0 adapters) finished. What we have: the old result survives a second wording of the instruction. Stating the removal explicitly ("there is no time limit") nearly eliminates the stale fill. A "this policy replaces the previous one" notice does not help. Not yet run: new seeds, new models, the second domain, the tool-log control and data mixing. Everything is one seed of one model (Qwen2.5-14B).

2. Results so far (Qwen2.5-14B, seed 0, cancellation domain)

Setup: the system prompt states only the other policy's fee rule. Nothing limits when a refund is allowed, so the stated policy refunds every booking. A "conflict item" is a booking older than the model's old window: the old rule denies it, the stated policy refunds it. Denying it means the old rule came back from the weights. The charts compare the adapter trained without the policy text in its prompts (blue) with a control trained on identical bookings and replies but with the policy text (orange).
